# 08. 壁打ち（AI）仕様

**優先度: P2** / 対応課題: C-09, C-10, C-18

現行の「AIコーチ」を **「壁打ち」** に改称し、制限の設計と応答方針を再構成します。

> **前提**: `03-spec-safety.md` を先に読んでください。セーフティ層は本機能の一部ではなく、**本機能より上位に位置する必須の関門**です。

---

## 1. 変更点の要約

| 項目 | 現行 | 新 |
|---|---|---|
| 名称 | AIコーチ | **壁打ち** |
| 自己記述 | 「あなた専用のアドバイス」 | 「考えを整理する相手」 |
| 無料の制限 | **月3回** | **1日1往復** |
| Pro | 無制限 | 無制限 ＋ **深い分析（週次・イベント前）** |
| 応答の型 | 共感 → 数値引用 → 単一アクション提案 | 受け止め → 問い返し **または** 選択肢の提示 |
| 数値の引用 | 「睡眠は20%を占めており、週0.3回」 | **禁止** |
| クライシス | 未確認 | **三層判定で遮断**（→ `03`） |
| 揺れの当日 | 制限あり | **Free でも無制限**（→ `05#6.4` S-27） |

## 2. なぜ変えるのか

### 2.1 「月3回」が最悪のゲーティングである理由

現行は**唯一の行動支援機能（action stage）を、週1回未満に制限**しています。

| 問題 | 説明 |
|---|---|
| 習慣が形成されない | 月3回では接触頻度が習慣化の閾値に届かない |
| 課金判断が習慣形成より先に来る | ユーザーは「価値を感じる前に」課金を迫られる |
| 唯一のリテンションドライバーを絞っている | 気分アプリで欠落している action stage（E-08）が、まさにここにある |

**変更**: 制限を「**回数**」から「**深さ**」へ移します。

| プラン | 通常の壁打ち | 深い分析 |
|---|---|---|
| Free | **1日1往復**（毎日使える） | なし |
| Pro | 無制限 | **あり**（週次のまとめコメント、揺れイベント前の備え提案、長い文脈での分析） |

「毎日ちょっと話せる」ことで習慣が作られ、「深く分析してほしい」で課金理由が生まれます。

### 2.2 応答品質が競合の最大の弱点であり、最大のリスク

Awarefy（App Store 4.3 / 7,047件）のレビューで最も多い不満（E-09、原文抜粋）:

> 「チェックインアウト時のAIの一言が当たり障りがない所か**オウム返し**な返事をされる上に『無理をなさらないでくださいね』と**定型文を毎回返される**」
>
> 「年間契約をしてしまったのですが、**今まで話した全ての事を覚えていてくれるわけではありません**」
>
> 「ストレスの原因を**勝手に夫婦間の揉め事だと思われた**」

muute のレビュー:

> 「**ネガティブを否定しないで欲しい。**『ネガティブ多い。来週は発見や喜びも報告してもらえると嬉しい』というインサイトが届いてがっかりした」

**現行アプリの実応答は、この失敗パターンの予備軍です。**

観察された応答（2026-08-01）:

> データを見ると、現在のポートフォリオで「睡眠」は20%を占めており、**週0.3回**取り組む大切な心の柱の一つとなっています。今週は…**10分早く布団に入る**という具体的なアクションを試してみませんか？

- パーソナライズは機能している（良い）
- しかし **「週0.3回」という機械的な数値引用は冷たく**、統計処理された感覚を与える
- 提案が汎用的（「10分早く布団に入る」は誰にでも言える）
- 3文構成のテンプレートが透けて見える（→ 「定型文」の指摘に直結）

### 2.3 規制の方向

| 事実 | 出典 |
|---|---|
| **イリノイ州法**は「AI therapy」「chatbot counselor」「virtual psychotherapist」等の**表示を、臨床医の直接的監督がない限り違法な誤認広告として扱う**（1違反あたり最大$10,000） | E-15 |
| 完全禁止4州（イリノイ・ネバダ・ロードアイランド・メイン）、規制4州。2026年Q1だけで36州70法案 | E-15 |
| APA: **生成AIは心理療法・治療・診断・クライシス支援に使用すべきでない** | E-11 |
| **Woebot は150万ユーザーを持ちながら、FDAのマーケティング承認要件を満たすコストと困難を理由に2025年6月に終了** | E-26 |
| Slingshot AI（累計$93M調達）は**規制上の明確な経路がないとして2026年1月に英国市場から撤退** | E-32 |

日本にはまだ同種の法規制がありませんが、**「コーチ」という職能名＋具体的な行動指示**は、この方向に対して不必要に露出しています。名称と出力の型を変えることは、コストがほぼゼロの予防策です。

### 3.1 使う言葉

| 用途 | 表記 |
|---|---|
| 機能名 | **壁打ち** |
| 説明 | 「考えを整理する相手」 |
| 入力欄プレースホルダ | 「いま思っていることを、そのまま」 |

### 3.2 使わない言葉

コーチ / カウンセラー / セラピスト / セラピー / カウンセリング / 診断 / 治療 / 症状 / 改善 / メンタルヘルスの専門家 / アドバイス

## 4. 応答の設計

### 4.1 応答の型

**「共感 → 分析 → 提案」の3段テンプレートをやめます。** それが「定型文」と呼ばれる形です。

代わりに、**状況に応じて型を切り替えます**。

| 型 | 使う場面 | 構造 |
|---|---|---|
| **A. 受け止めるだけ** | ユーザーが吐き出しているとき（多数） | 受け止め1〜2文。**提案しない。質問もしない** |
| **B. 問い返す** | 状況が曖昧なとき | 受け止め ＋ 短い問い1つ |
| **C. 選択肢を出す** | ユーザーが明示的に「どうしたらいい？」と聞いたとき | 受け止め ＋ **2〜3の選択肢**（1つに絞らない） |
| **D. 事実を思い出させる** | 揺れイベントが近い / 支えの記録があるとき | 受け止め ＋ 「そういえば〈木曜のバンド〉がありますね」 |
| **E. 黙る** | セーフティ `block` | AIは応答しない（→ `03#4`） |

**既定は A です。** 提案は求められたときだけ行います。

> 根拠: emol CEO の指摘「**相槌でも何でもいいからリアクションがほしい。AIが『そうなんだ、大変だね』と反応してくれるだけでも心が楽になる**」（E-33）。ユーザーが求めているのは治療ではなくリアクションです。

### 4.2 型の選択規則

```
セーフティ判定
  ├─ block   → 型E（AI呼び出しなし）
  └─ clear / caution
       ↓
  ユーザーの発話に「どうしたらいい/どうすれば/アドバイス」等の要求があるか
       ├─ ある  → 型C
       └─ ない
            ↓
       揺れイベントが D-7 以内、または直近の点検データに言及の余地があるか
            ├─ ある（かつ2往復目以降）→ 型D
            └─ ない
                 ↓
            発話が具体的な状況説明か、感情の吐露か
                 ├─ 曖昧      → 型B（1往復目のみ）
                 └─ 吐露      → 型A
```

**制約: 1つの会話で型D（データ言及）は最大1回。** 毎回データに言及すると「統計されている感」が出ます。

### 4.3 禁止事項（プロンプト・実装の両方で担保）

| ID | 禁止 | 理由 |
|---|---|---|
| AI-01 | **数値の引用**（「20%」「週0.3回」「3本」） | 冷たい。統計処理された感覚。C-10 |
| AI-02 | 「〜すべきです」「〜しましょう」「〜が必要です」 | 指示。規制の方向にも逆行 |
| AI-03 | ネガティブな内容への評価（「ネガティブが多いですね」） | muute の失敗の再現（E-09） |
| AI-04 | 前週・前回との比較（「先週より少ないですね」） | 判定（原則1） |
| AI-05 | 原因の推測（「ご家族との関係が原因では」） | Awarefy の「勝手に夫婦間の揉め事だと思われた」（E-09） |
| AI-06 | 診断名・症状名の使用（「うつ」「不安症」「ADHD」） | `03#7.2` |
| AI-07 | 「私も同じです」「私は嬉しいです」等、AI自身の感情の主張 | 人格の偽装。APA が警告する誤った安堵（E-11） |
| AI-08 | 同一の定型句を連続する応答で繰り返す（「無理をなさらないでくださいね」） | Awarefy の最多不満（E-09） |
| AI-09 | 1回の応答で複数の提案を並べる（型C の2〜3選択肢は例外） | 宿題化 |
| AI-10 | 200文字を超える応答 | 長文は読まれない。かつテンプレ感が出る |

**AI-01 と AI-08 は実装側で機械的に検査可能です。** 応答生成後に正規表現でチェックし、該当したら再生成する後処理を入れてください（プロンプトだけに頼らない）。

### 4.4 記憶（コンテキスト）

Awarefy の課金者の不満は「**記憶しない**」でした。同じ失敗を避けます。

| 対象 | 渡すか | 内容 |
|---|---|---|
| 同一スレッド内の会話 | ○ | 全量（トークン上限まで） |
| 過去のスレッド | **要約のみ** | 直近4週の会話から生成した短い要約（500文字以内）。全文は渡さない |
| 柱の一覧 | ○ | ラベルと `kind` のみ。`importance` や `level` の**数値は渡さない**（AI-01 の担保） |
| 直近4回の週次点検 | ○ | 「選ばれた柱の名前」のみ。回数・割合は渡さない |
| 揺れイベント | ○ | タイトル・日付・残り日数 |
| `mood_note` / `ShakeReview.note` | ○ | 直近3件まで |

**「数値をAIに渡さない」ことが AI-01 の最も確実な担保です。** 渡さなければ引用できません。

### 4.5 スレッドのリセット

現行には「新しい会話を始める」ボタンがあります。**維持します**（文脈を切りたいニーズは正当）。ただし:

- リセット後も §4.4 の「過去スレッドの要約」は引き継ぐ（「全部忘れられた」感を防ぐ）
- リセット時に確認ダイアログを出す（誤操作防止）

## 5. 制限（レート）

### 5.1 仕様

| プラン | 制限 | リセット |
|---|---|---|
| Free | **1日1往復**（ユーザー発話1回＋AI応答1回） | 毎日 04:00（ユーザーTZ） |
| Pro | 無制限（ただし濫用防止の上限として1日100往復） | — |

### 5.2 例外: 揺れの当日は Free でも無制限

`ShakeEvent.status = today` の日は、**Free ユーザーの制限を解除**します（→ `05#6.4` S-27）。

理由:
- 最も必要な日に「上限に達しました」を出すのは、プロダクトの約束に反する
- この体験が最も強い課金動機になる（体験してから課金する順序が正しい）

### 5.3 上限到達時の表示

```
┌──────────────────────────────────────────┐
│  今日はここまでです。                     │
│  また明日、話しましょう。                 │
│                                          │
│  ── しんどいときは ──                     │
│  よりそいホットライン 0120-279-338        │
│  （24時間・無料）        [電話をかける]    │
│                                          │
│  ▸ Pro なら、いつでも話せます             │
└──────────────────────────────────────────┘
```

**要件**

| ID | 要件 |
|---|---|
| AI-20 | 上限到達時に**必ず相談窓口を表示する**（課金訴求だけを出さない） |
| AI-21 | 課金訴求は最下部に小さく1行。モーダルで被せない |
| AI-22 | 上限到達時でも、**セーフティ判定は動く**（`block` なら窓口カードを出す） |
| AI-23 | 上限のカウントは「往復」単位。AI応答が失敗した場合はカウントしない |

## 6. 深い分析（Pro）

Pro の課金理由を「無制限」だけに置くと、価値が「量」になります。**「深さ」に置き換えます。**

| 機能 | 内容 | タイミング |
|---|---|---|
| **今週のひとこと** | 週次点検の結果に対する短いコメント | 点検完了時（→ `06#4.3`） |
| **備えの提案（AI分）** | ルールベース2件に加えて、AI生成1件 | 揺れイベント D-14（→ `05#5.3`） |
| **揺れの前の整理** | 揺れイベント D-3 に、過去のふりかえりを踏まえた長めの整理（400文字程度） | D-3、1回のみ |
| **ふりかえりの言語化** | `ShakeReview` 完了後、「効いた支え」を踏まえた短い記録コメント | ふりかえり完了時 |

**すべてに §4.3 の禁止事項が適用されます。** 「深い」は文字数ではなく、文脈の参照範囲が広いことを意味します。

## 7. 障害時の挙動

| 状況 | 挙動 |
|---|---|
| セーフティ第2段（分類器）がタイムアウト | **`caution` にフォールバック**（→ `03#3.4`）。`clear` にしない |
| 応答生成が失敗 | 「うまく言葉が出てきませんでした。もう一度送ってもらえますか」。**往復カウントを消費しない** |
| 応答生成がタイムアウト（15秒） | 同上 |
| §4.3 の後処理検査に引っかかった | 1回だけ再生成。2回失敗したら型A（受け止めのみ）の固定文にフォールバック |
| AI が完全に利用不可 | 壁打ちタブを非表示にする。**他機能（揺れ予報・週次点検）は全て動くこと**（→ `05` SF-A-14） |

## 9. 計測

| 指標 | 定義 | 目標 |
|---|---|---|
| 壁打ち利用率（Free） | 週に1回以上使ったFreeユーザー | **40%**（現行の月3回制限下より大幅に上がることが変更の検証） |
| 平均往復数（Pro） | Pro の1週あたり往復数 | 観測 |
| **「的外れ」報告率** | 全応答に対する報告 | **3%未満**（これが応答品質の一次指標） |
| 型の分布 | A/B/C/D の比率 | **型A が50%以上**（提案しすぎていないかの検証） |
| 後処理リジェクト率 | §4.3 検査で再生成された割合 | 5%未満（高い場合はプロンプトを改善） |
| 当日無制限からの課金転換 | 揺れ当日に壁打ちを3往復以上したFreeユーザーの、7日以内の課金率 | 観測（→ `10` の主要導線） |
| 上限到達率（Free） | 1日1往復を使い切った割合 | 観測。**高いこと自体は問題ではない** |
| セーフティ発火率 | → `03#9` | |

**注意**: 「壁打ちの利用回数」を上げることを目標にしてはいけません。回数が多いことは、依存の形成を意味する可能性もあります。品質指標（「的外れ」報告率）と型の分布を主に見てください。
